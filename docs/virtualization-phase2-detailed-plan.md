# 虚拟化平台管理二期：详细实施方案

## 目标
1. 提升纳管准确性：纳管前给出冲突预检查与建议目标主机。
2. 提升可视化体验：拓扑视图从树形改为层级卡片，增加资源汇总。
3. 提升联动效率：虚机纳管后可快速定位到资产主机。

## 范围拆分
### A. 纳管预检查与冲突策略
1. 新增预检查接口：`GET /api/v1/virtualization/guests/{id}/precheck?assetHostId=`。
2. 检查项：
- IP 精确匹配（同IP资产主机）
- 同名主机冲突（同名多个资产主机）
- 历史绑定冲突（已绑定到其他主机）
- 目标主机与IP匹配一致性
3. 输出：`riskLevel`（none/low/medium/high）、检查明细、候选主机、建议主机。
4. 前端纳管弹窗增加预检查面板与“一键使用建议主机”。

### B. 拓扑视图增强
1. 增加汇总卡片：平台数、集群数、宿主机数、虚机数。
2. 平台-集群-宿主机采用卡片化布局，突出状态与关键指标。
3. 保留平台筛选，支持快速刷新。

### C. 纳管联动增强
1. 在虚机列表中强化绑定信息展示。
2. 预留“跳转主机详情”入口（本轮先完成数据与按钮位，下一轮接主机详情锚点能力）。

## 数据与接口设计
### 1) 预检查返回结构
```json
{
  "guestId": 101,
  "guestName": "node-01",
  "primaryIp": "10.0.0.12",
  "riskLevel": "medium",
  "currentBinding": {"id": 88, "name": "prod-node-01", "ip": "10.0.0.12"},
  "selectedHost": {"id": 90, "name": "prod-node-02", "ip": "10.0.0.13"},
  "suggestedHost": {"id": 88, "name": "prod-node-01", "ip": "10.0.0.12", "matchType": "ip_exact"},
  "candidateHosts": [
    {"id": 88, "name": "prod-node-01", "ip": "10.0.0.12", "matchType": "ip_exact"}
  ],
  "checks": [
    {"code": "ip_exact_match", "level": "low", "message": "发现同IP资产主机"},
    {"code": "selected_host_ip_mismatch", "level": "high", "message": "所选主机与IP匹配主机不一致"}
  ]
}
```

### 2) 风险分级规则
1. `high`：已绑定其他主机、所选目标与IP匹配主机冲突、同名多主机冲突。
2. `medium`：虚机缺少IP、无法自动匹配主机、需要人工确认。
3. `low`：存在可靠匹配（IP/唯一同名）且无冲突。
4. `none`：无有效风险项。

## 实施计划
### 第1批（已启动）
1. 后端预检查接口与规则引擎。
2. 前端纳管弹窗预检查与建议主机按钮。
3. 拓扑视图卡片化改版与汇总指标。
4. PVE账号输入提示（realm 建议）。

### 第2批（下一步）
1. 纳管冲突策略配置化（严格/宽松模式）。
2. 虚机详情页增加“纳管变更历史”。
3. 主机详情联动跳转闭环。

### 第3批（二期收尾）
1. 同步后状态回流（主机在线/离线映射到虚机视图）。
2. 趋势图（按平台维度展示虚机状态变化）。
3. 二期验收与回归测试清单。

## 验收标准
1. PVE 用户填写 `root` 时可自动兼容 realm 并同步成功。
2. 纳管弹窗可展示风险等级、检查项、建议主机。
3. 选择建议主机后可完成纳管。
4. 拓扑页面可看到平台/集群/宿主机卡片与总览指标。
5. 不影响现有平台管理与同步功能。
