# 虚拟化平台管理实施路线图（ESXi / PVE）

## 背景
当前 `资产管理` 已有主机、云账号、凭据、分组、审计等能力，但对 ESXi / PVE 这类虚拟化平台缺少统一的发现与展示入口。实际需求不是简单新增一个账号类型，而是需要呈现 `平台 -> 集群/宿主机 -> 虚拟节点` 的层级关系，并支持将虚拟节点纳管到主机资产。

## 目标
1. 统一接入 `vCenter`、`独立 ESXi`、`PVE`。
2. 实现只读发现、拓扑展示、虚拟节点列表筛选。
3. 支持将虚拟节点一键纳管到现有主机体系。
4. 后续逐步增加电源、快照、控制台跳转等操作能力。

## 设计原则
1. `云账号` 与 `虚拟化平台` 分离建模，不混用同一模块。
2. 先做读能力再做写能力，先做低风险增量。
3. 同步数据与主机手工维护字段隔离，避免覆盖用户人工配置。
4. 平台发现与主机运维解耦：发现到纳管是两段式流程。

## 一期（MVP）
### 范围
1. 虚拟化平台管理：新增、编辑、删除、启停状态、连通性测试。
2. 平台同步：手动同步、定时同步、同步日志与错误信息。
3. 资产展示：
- 树形拓扑：`平台 -> 集群 -> 宿主机`
- 节点列表：`VM / LXC`
4. 纳管：虚拟节点一键纳管为主机资产，并建立绑定关系。
5. 基础筛选：按平台类型、平台、集群、宿主机、电源状态、是否已纳管筛选。

### 不包含
1. 开关机、重启、快照、迁移、删除等高风险写操作。
2. 嵌入式 noVNC / VMware Console。
3. 容量超分比分析与告警联动。

### 交付结果
1. 新模块页面：`资产管理 -> 虚拟化平台`。
2. 新增后端表与接口（见《第一期表结构和接口草案》）。
3. 接入层支持：`vCenter`、`独立 ESXi`、`PVE` 的只读发现。

## 二期（增强）
### 范围
1. 平台详情页增强：
- 宿主机资源汇总
- 集群资源汇总
- 虚拟节点状态趋势
2. 纳管协同增强：
- 纳管冲突策略（IP 重复、同名主机、多平台同一节点）
- 纳管预检查与差异对比
3. 运维联动：
- 从虚拟节点详情跳转到已纳管主机详情
- 纳管后状态回流（主机在线状态回写到虚拟节点视图）

### 不包含
1. 平台级写操作（开关机/快照等）仍默认关闭。

## 三期（操作能力）
### 范围
1. 平台写操作（按权限开关）：
- 开机/关机/重启
- 快照创建/恢复/删除
2. 控制台跳转：
- PVE noVNC 透传
- VMware Console 链接透传
3. 风险审计与授权：
- 高风险操作二次确认
- 审计日志结构化记录
- 细粒度 RBAC（按平台/集群/宿主机）

## 关键风险与处理
1. Guest Agent 缺失导致 IP/OS 不准：
- 标记数据来源和可信度，界面显示“采集可信度”。
2. ESXi / vCenter 层级不同：
- 通过 Provider Adapter 归一化输出模型。
3. PVE VM 与 LXC 字段差异大：
- 统一 guest 抽象，`guest_type` 区分语义。
4. 纳管覆盖风险：
- 禁止同步任务直接改写主机资产的人工字段。

## 实施建议
1. 先落地一期完整闭环（发现 -> 展示 -> 纳管）。
2. 二期再做统计、冲突策略、体验增强。
3. 三期再开放写操作并配套审计。
