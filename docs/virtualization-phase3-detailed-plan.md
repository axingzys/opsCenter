# 虚拟化平台管理三期：详细实施方案

## 目标
1. 在现有只读发现与纳管基础上，逐步开放受控写操作。
2. 为高风险动作补齐二次确认、原因留痕、结构化审计。
3. 保持默认安全：不开启写操作时，不影响当前平台管理与纳管能力。

## 范围
### A. 平台写操作
1. 虚机电源操作：开机、关机、重启。
2. 快照操作：创建、恢复、删除。
3. 平台差异通过 provider adapter 归一化。

### B. 控制台跳转
1. PVE noVNC 链接透传。
2. VMware Console / Web Console 链接透传。
3. 跳转前校验权限、有效期与目标存在性。

### C. 风险审计与授权
1. 高风险操作二次确认。
2. 操作原因必填配置化。
3. 操作审计日志结构化记录。
4. 细粒度 RBAC：平台 / 集群 / 宿主机 / 虚机。

## 分批计划
### 第1批（基础骨架）
1. 新增操作审计表 `virtualization_action_logs`。
2. 预留三期接口草案与字段模型。
3. 梳理风险等级与操作分类。

### 第2批（电源操作）
1. 后端开放 `power_on / power_off / reboot` 能力。
2. 按 provider 适配 PVE / ESXi 实际执行。
3. 页面增加操作入口、二次确认与结果提示。
4. 审计日志落库。

### 第3批（快照与控制台）
1. 快照创建 / 恢复 / 删除。
2. 控制台透传跳转。
3. 补平台权限控制与审计查询页面。

### 第4批（安全门禁与控制台收口）
1. 写操作总开关默认关闭，未开启时仅允许只读能力。
2. 电源与快照操作按总开关统一拦截，并保留审计记录。
3. ESXi 控制台生成 HTML5 链接。
4. PVE 控制台生成平台跳转链接，并明确登录态要求。
5. 页面补控制台入口与写操作状态提示。

## 风险分级
1. `low`：只读控制台跳转。
2. `medium`：开机、关机。
3. `high`：重启、快照恢复、快照删除。

## 默认策略
1. 三期写操作默认关闭。
2. 未配置审批/确认策略时，只允许保留只读能力。
3. 任意执行失败都必须留审计日志。
