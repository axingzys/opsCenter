# 数据库管理三期：详细实施方案

## 目标
1. 在一期、二期只读与统一审计闭环基础上，逐步开放受控写操作和逻辑备份能力。
2. 保持默认安全：三期能力默认不影响现有实例纳管、结构浏览、只读查询、诊断与审计链路。
3. 优先完成 MySQL / PostgreSQL 三期最小闭环，其他数据库类型按适配器能力分批跟进。

## 现状回顾
当前数据库管理一、二期已经完成的稳定能力：

1. 数据库实例纳管、凭据绑定、连接测试、元数据同步、结构浏览。
2. MySQL / PostgreSQL 一期主链路已完成真实联调；SQL Server / ClickHouse / Oracle 已完成二期代码接入。
3. 只读 SQL 控制台、格式化、历史记录、查询结果导出、执行计划。
4. 数据字典导出、慢 SQL、活跃会话、基础诊断指标。
5. 统一查询审计：已覆盖 `query`、`explain`、`query_export`、`metadata_export`、`diagnosis_metrics`、`diagnosis_sessions`、`diagnosis_slow_queries`。

## 代码回顾结论
为了避免三期直接改坏现有一期、二期链路，当前实现里有几个明确约束：

1. 统一审计已经收口到 `database_query_audits`，三期应继续扩展这条链路，不要再并行新增一套“写操作单独审计表”。
2. 当前只读执行链路是 `ExecuteQuery / ExplainQuery / ExportQuery -> AnalyzeReadOnlySQL* -> runAuditedQuery -> executeSQLQuery`。
   写操作不能直接在 `AnalyzeReadOnlySQL*` 上硬改，应该新增独立的写操作分析与执行入口。
3. 当前 `executeSQLQuery` 是面向 `QueryContext + 行结果读取` 的只读实现。
   三期写操作必须拆出 `ExecContext` 路径，单独记录 `RowsAffected`、风险等级、原因、确认状态和回滚辅助信息。
4. 当前前端数据库页面仍是单页工作台 `DatabaseManagement.vue`。
   三期不建议突然拆成多个完全独立页面，优先沿现有 Tabs / 工具栏 / 抽屉 / 弹窗模式渐进扩展。
5. 当前系统配置已经通过 `sys_config` 和 `ConfigUseCase` 提供稳定入口。
   三期的写开关、确认策略、影响行数阈值、备份默认参数应先进入配置体系，再接入数据库执行链路。

## 三期范围
### A. 受控写操作门禁
1. 写操作总开关。
2. 写操作独立权限点。
3. 按风险等级区分不同拦截策略。
4. 默认禁止多语句写入。
5. 默认禁止 `DROP`、`TRUNCATE`、无条件 `UPDATE / DELETE`。

### B. SQL 风险识别与预检查
1. 识别 `INSERT / UPDATE / DELETE` 等 DML 写操作，并将 DDL 结构变更拆到独立通道。
2. 标记 `low / medium / high / critical` 风险等级。
3. 提供“执行前校验”结果，包括：
   - SQL 类型
   - 风险等级
   - 是否需要二次确认
   - 是否需要填写原因
   - 是否触发默认拦截规则
4. 预留最大影响行数限制。

### C. 写操作执行与统一审计
1. 执行前写入 `pending` 审计。
2. 审计记录补充：
   - 审计动作
   - 风险等级
   - 原因
   - 是否需要确认
   - 是否已确认
   - 影响行数上限
   - 回滚 SQL 辅助内容
3. 执行后回写状态、耗时、影响行数、错误信息。

### D. 回滚 SQL 辅助
1. MySQL / PostgreSQL 优先支持基础回滚辅助。
2. 先覆盖简单 `INSERT / UPDATE / DELETE` 场景。
3. 复杂场景允许只返回“暂不支持自动生成”的明确提示。
4. 回滚 SQL 只做辅助，不等同于恢复保证。

### E. 逻辑备份
1. 备份任务配置。
2. 手动执行备份。
3. 定时备份计划。
4. 备份记录落库。
5. 本地文件存储与下载。
6. 保留策略清理。

### F. 备份联动与告警
1. 备份失败记录。
2. 失败告警预留。
3. 备份成功率可被后续巡检或告警模块消费。

## 三期暂不包含
1. 审批流。
2. 生产恢复执行。
3. 对象存储、多存储后端。
4. 数据库账号生命周期管理。
5. 复杂 Schema Diff。
6. 自动 SQL 优化建议。

## 分批计划
### 第 1 批：基础底座
目标：把三期涉及的配置、模型和后续扩展点先落稳。

子项：

1. 新增三期详细方案与表结构 / 接口草案文档。
2. 新增数据库三期系统配置项：
   - 写操作总开关
   - 高风险确认开关
   - 操作原因必填开关
   - 最大影响行数
   - 默认备份保留天数
   - 本地备份目录
3. 扩展统一审计模型字段，预留写操作原因、确认状态、影响行数上限、回滚 SQL。
4. 新增备份任务表与备份记录表模型。
5. AutoMigrate 接入三期新增模型。

验收点：

1. 服务启动后能自动补齐新的数据库配置默认值。
2. 数据库三期新增表能自动创建。
3. 一期、二期现有接口和审计列表不受影响。

### 第 2 批：写操作门禁与预检查
目标：先做“能判断、能拦截、不能误放行”。

子项：

1. 新增写操作 SQL 分析器：
   - 识别 SQL 类型
   - 识别风险等级
   - 识别危险模式
2. 新增写操作预检查接口。
3. 从系统配置读取写开关、确认策略、影响行数限制。
4. 审计动作补充：
   - `change_execute`
   - `ddl_execute`
   - 后续可扩 `change_validate`
5. 增加单元测试：
   - 禁止多语句
   - 禁止无 WHERE 的更新 / 删除
   - 禁止 `DROP / TRUNCATE`
   - 风险等级归类

验收点：

1. 写开关关闭时，任意写 SQL 都会被拦截。
2. 能正确返回 SQL 类型、风险等级和拦截原因。
3. 现有只读 SQL 校验测试全部通过。

### 第 3 批：写操作执行最小闭环
目标：先开放最小可控写能力，不追求一步到位。

子项：

1. 新增写操作执行接口。
2. 仅支持单语句执行。
3. 支持原因必填。
4. 支持高风险二次确认参数。
5. 执行后返回：
   - 审计 ID
   - SQL 类型
   - 影响行数
   - 执行耗时
   - 回滚 SQL 辅助内容
6. 审计状态完整回写。

验收点：

1. `INSERT / UPDATE / DELETE` 能在开关开启且权限满足时执行。
2. 高风险 SQL 未确认时会被拒绝并留痕。
3. 写操作会记录影响行数和操作原因。

### 第 4 批：回滚 SQL 辅助与前端确认流
目标：提升写操作可控性和可回溯性。

子项：

1. MySQL / PostgreSQL 简单 DML 回滚 SQL 生成。
2. 前端执行前确认弹窗：
   - 风险等级
   - 原因输入
   - 是否继续执行
3. 写操作结果区新增：
   - 影响行数
   - 回滚 SQL 预览
   - 审计链接
4. 审计详情补充写操作字段展示。

验收点：

1. 用户能在页面完成高风险确认。
2. 简单 DML 能看到回滚 SQL 辅助内容。
3. 查询历史不会混入写操作回填。

### 第 5 批：备份任务配置
目标：先完成备份任务建模和手动触发入口。

子项：

1. 备份任务 CRUD。
2. 任务字段：
   - 实例
   - 名称
   - 备份类型
   - cron 表达式
   - 存储类型
   - 保留天数
   - 启停状态
3. 手动执行备份接口。
4. 备份相关权限点。
5. 备份审计动作补充：
   - `backup_run`
   - `backup_download`

验收点：

1. 能创建、编辑、启停、删除备份任务。
2. 能手动触发一条备份任务。
3. 备份任务默认写入本地目录，不依赖额外对象存储。

### 第 6 批：备份执行与记录
目标：形成备份执行闭环。

子项：

1. MySQL 使用 `mysqldump`。
2. PostgreSQL 使用 `pg_dump`。
3. 记录备份文件路径、文件大小、耗时、状态、错误信息。
4. 清理过期备份文件。
5. 提供备份记录下载接口。
6. 失败场景返回明确错误，例如：
   - 客户端命令不存在
   - 目录不可写
   - 凭据错误
   - 网络不可达

验收点：

1. 手动备份成功后生成文件与记录。
2. 失败时记录可检索，且不会误标成功。
3. 下载接口只允许下载存在且属于当前记录的文件。

### 第 7 批：定时调度与告警收口
目标：让备份从“手动能跑”变成“持续能用”。

子项：

1. 定时调度器加载启用中的备份任务。
2. 支持任务变更后刷新计划。
3. 失败告警事件预留给监控 / 告警模块。
4. 备份执行与下载统一写入审计。
5. 前端补备份任务、备份记录和失败提示。

验收点：

1. 定时任务按计划执行。
2. 停用任务后不再继续调度。
3. 失败备份能在页面和审计中定位。

### 第 8 批：联调与回归验收
目标：在真实实例上验证三期最小可用。

联调清单：

1. MySQL：
   - 写开关关闭拦截
   - 简单 `INSERT / UPDATE / DELETE`
   - 高风险确认
   - 手动备份
2. PostgreSQL：
   - 写开关关闭拦截
   - 简单 `INSERT / UPDATE / DELETE`
   - 手动备份
3. 审计：
   - 变更动作筛选
   - 备份动作筛选
   - 原因 / 确认 / 回滚内容展示
4. 回归：
   - 只读查询
   - Explain
   - 导出
   - 诊断
   - 查询历史

4. `backup_download`

## 风险分级建议
1. `low`：只读查询、Explain、元数据导出、诊断查看。
2. `medium`：受控导出、手动备份、低影响 INSERT。
3. `high`：UPDATE、DELETE、DDL、批量 INSERT。
4. `critical`：DROP、TRUNCATE、无条件 UPDATE / DELETE、生产恢复。

## 默认策略
1. 三期写操作默认关闭。
2. 高风险 SQL 默认要求确认。
3. 操作原因默认必填。
4. 默认禁止多语句写入。
5. 默认禁止 `DROP / TRUNCATE`。
6. 默认限制最大影响行数。
7. 备份默认写入本地目录。
8. 任意写操作和备份操作都必须留审计。
